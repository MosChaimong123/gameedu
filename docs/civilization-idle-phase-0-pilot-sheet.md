# Civilization Idle Phase 0: staging pilot sheet

สถานะ: แบบบันทึกสำหรับทดสอบด้วยคนจริง ยังไม่ใช่ผลทดสอบ
อ้างอิง: [baseline report](./civilization-idle-phase-0-baseline-report.md), [staging/pilot runbook](./civilization-idle-pilot-runbook.md)

## ก่อนเริ่ม

- ผู้รับผิดชอบกำหนดวันทดสอบและผู้เฝ้าดูระบบ; ขอความยินยอมผู้เข้าร่วมตามนโยบายโรงเรียนก่อนจดผล
- ใช้ staging และบัญชี/ห้องทดสอบที่แยกจาก production; อย่าใช้ชื่อจริง อีเมล รหัสเข้าห้อง หรือภาพหน้าจอที่เผยข้อมูลนักเรียนในแบบบันทึกนี้
- ทำ preflight, backup, QA และ dark deploy ตาม runbook; ตั้ง `CIVILIZATION_IDLE_PILOT_CLASSROOM_IDS` เป็น ObjectId ห้องทดสอบ **ก่อน** เปิด `CIVILIZATION_IDLE_ENABLED=true` และยืนยันห้องอื่นยังเข้าไม่ได้
- ทดลองเปิด/ปิด flag และกู้การเข้าถึงเซฟเดิมก่อนเชิญผู้เข้าร่วมจริง
- สุ่ม `pilot_id` แบบใช้ครั้งเดียวที่ไม่มีความสัมพันธ์กับ Student ID; เก็บเอกสารจับคู่ผู้เข้าร่วมแยกต่างหากเฉพาะผู้รับผิดชอบ หากไม่จำเป็นไม่ต้องมีเอกสารจับคู่

| ตัวอย่าง `P01` | อิสระ | เวลา staging | 0 | - | - | - | 0 | 0 | 0 | ยังไม่เริ่ม | - |

ใช้เวลาเริ่มและ milestone ใน timezone เดียวกัน; `active นาที` คือเวลาที่เปิดและใช้งานจริง ไม่รวมเวลาออกจากเกม. ห้ามแทนค่าที่ไม่ทราบด้วย 0 ให้ใช้ `-`. ระบุว่าคำสั่งที่ทำเป็นการตัดสินใจของคน ไม่ใช่ scripted baseline. หากผู้เข้าร่วมไม่อยากให้บันทึกข้อมูล ให้หยุดเก็บผลทันที

## คำถามหลังแต่ละ session

1. ตอนกลับมา คุณรู้ไหมว่าทรัพยากรเพิ่มเท่าไรและติดอะไรอยู่?
2. มีทางเลือกที่มีความหมายภายใน 1-3 นาทีแรกหรือไม่? ถ้าไม่มี ติดอะไร?
3. ระหว่างเล่น คุณเลือกวิจัย/อาคาร/คนงานเพราะเหตุใด? มีอย่างน้อยสองทางที่น่าลองหรือไม่?
4. เคยกลับมา 3 ครั้งติดโดยไม่มีสิ่งใหม่ให้ตัดสินใจหรือไม่?
5. มีจุดที่ไม่เข้าใจว่าต้องทำอะไรเพื่อไป Bronze หรือจบ Bronze หรือไม่?

สรุปคำตอบเป็นประเด็น ไม่จดข้อความที่อาจระบุตัวผู้เรียน. แยกปัญหาเป็น `balance`, `UX`, `data integrity`, `access control` ตาม runbook

## เกณฑ์ปิด Phase 0

- มีผลเล่นจริง Stone/Bronze จากกลุ่มสมัครใจมากพอให้เห็นแนวโน้มหลายรูปแบบ ไม่ใช้ผลจำลอง 4 กลยุทธ์แทนคนจริง
- รายงานเวลาแบบแยก **calendar elapsed**, **active minutes** และ **offline simulated/discarded**; คำนวณค่ากลางเฉพาะกลุ่มที่เล่นถึง milestone และรายงานจำนวนคนที่ยังไม่ถึงด้วย
- ไม่มี softlock, เซฟหาย, ข้ามห้อง หรือผลกระทบต่อคะแนน/Gold/งานห้องเรียน; หากพบให้ปิด flag แล้วทำตาม rollback ทันที
- รายการคอขวดและช่วงที่ไม่มีการตัดสินใจใหม่ถูกจัดลำดับแก้ใน Phase 1/2; รับรองหรือปรับเป้า 500 ชั่วโมงจากข้อมูลจริง ไม่ปรับต้นทุนเพื่อไล่ตัวเลขอย่างเดียว

เมื่อจบ pilot ให้ลบแบบบันทึกรายคนตามช่วงเวลาที่ผู้รับผิดชอบกำหนดไว้ล่วงหน้า เก็บได้เฉพาะผลสรุปที่ไม่ระบุตัวตน ห้าม commit ข้อมูล pilot รายคนหรือ secret ลง repo
