# Civilization Idle: ตารางตัวละครหลักประจำเมือง

สถานะ: ข้อเสนอกติกาเพื่อ playtest ยังไม่ได้ implement | 25 พฤศจิกายน 2026

ใช้คู่กับ [แผน 500 ชั่วโมง/5 ยุค](./civilization-idle-500-hour-roadmap.md). ปัจจุบัน GameEdu มีเนื้อหาเล่นได้ 2 ยุคเท่านั้น; ตัวละครของอีก 3 ยุคยังเป็นการออกแบบล่วงหน้า ตัวเลขทุกตัวในเอกสารนี้เป็น **ค่าเริ่มต้นทดลอง** ไม่ใช่ balance ที่รับรองแล้ว

## กติกากลาง

- ตัวละคร 20 ตัว: ยุคละ 4 ตัว ซื้อได้เมื่อถึงยุคของตัวนั้น แต่ **แต่งตั้งได้ครั้งละ 1 ตัว**; สลับฟรีเมื่ออยู่หน้าเมือง ไม่ทำให้การซื้อ/ผลิตย้อนหลัง
- ซื้อระดับ 1 แล้วเป็นเจ้าของถาวร; อัปเกรดต่อถึงระดับ 5. ระดับและการเป็นเจ้าของคงอยู่หลังจบอวกาศ/รีเซ็ต แต่ความสามารถที่อ้างถึงระบบยุคหลังจะยังไม่ทำงานจนกว่ารอบใหม่ปลดล็อกระบบนั้น
- ค่าหลักในตารางคือโบนัสเมื่อ **แต่งตั้ง** เท่านั้น; ไม่มีโบนัสสะสมจากตัวที่เก็บไว้ในคลัง. ระดับ 3 และ 5 เปิดลูกเล่นเฉพาะ โดยรายละเอียดด้านล่างระบุผลที่ไม่ซ้อน/ไม่ทำงานย้อนหลัง
- ไม่มีตัวไหนเป็นเงื่อนไขผ่านยุคหรือสร้างทรัพยากรฟรีโดยไม่ใช้ input. รางวัล Prestige หนึ่งชิ้นต่อรอบเป็นอีกระบบหนึ่ง; ต้องทดสอบเพดานเมื่อซ้อนกับตัวละคร
- โบนัสบวกชนิดเดียวกันให้รวมแบบ additive ก่อนคูณกับ base rate, เช่น base `1.0/s`, วิจัย `+15%`, ผู้นำ `+12%` = `1.27/s` ไม่ใช่ `1.15 * 1.12`. โบนัสลดต้นทุน/การบริโภคมีเพดานรวม `30%` และปัดราคาขึ้นเป็นจำนวนเต็มอย่างน้อย 1; cooldown ไม่ต่ำกว่า floor ของกิจกรรมนั้น
- ตัวเลขที่แสดงใน UI ต้องระบุฐานคำนวณ, ผลก่อน/หลังแต่งตั้ง, gross/net และสาเหตุหยุดผลิต. ห้ามแสดงโบนัสของระบบที่ยังไม่ปลดล็อกว่าได้ผลแล้ว

## เศรษฐกิจแต้มพิเศษเมือง

**แยกบัญชีจากคะแนนงานวิชาการ, `behaviorPoints` และ Gold.** งานที่ครูเปิดสิทธิ์และยืนยันว่าเสร็จให้แต้มพิเศษเมือง 3 แต้ม/งาน/นักเรียน/ครั้ง โดยไม่หักคะแนนเก็บเมื่อนำไปซื้อ ตัวเลข 3 แต้มเป็นสมมติฐานต้องเทียบกับจำนวนงานจริงของห้อง; ไม่ผูกกับระดับคะแนนหรืออันดับในห้อง งานเดิมที่แก้ไข/ส่งซ้ำต้องไม่จ่ายซ้ำ ครูเลือกเปิดรายห้องและมีเพดานแต้มต่อช่วงที่ประกาศชัดเจน หากห้องมีงานน้อยจนซื้อไม่ได้ต้องปรับราคา/อัตราอย่างเป็นธรรมก่อนเปิด ไม่แก้ด้วยการให้คะแนนวิชาการเพิ่ม

### รับแต้ม จ่ายแต้ม และยอดคงเหลือ

1. **รับ:** เมื่องานที่ครูเปิดรับแต้มพิเศษเปลี่ยนเป็นสถานะเสร็จตามเกณฑ์ที่ครูประกาศ ฝั่งเซิร์ฟเวอร์เพิ่ม `+3` ให้กระเป๋าเมืองของ `Student.id` นั้นครั้งเดียว พร้อม ledger อ้าง `assignmentId + studentId + rewardType`. งานที่ยังไม่เสร็จหรือไม่ได้เปิดรับแต้มให้ `0`. ตัวเลขคะแนนวิชาการเป็นเพียงหลักฐานการทำงาน ไม่ถูกโอนหรือหักไปซื้อเกม
2. **ซื้อ:** ต้องมี `balance >= price`, ถึงยุคปลดล็อก และยังไม่เป็นเจ้าของ. ฝั่งเซิร์ฟเวอร์หักราคาเต็มและสร้างระดับ 1 พร้อม receipt เดียวกัน; ถ้าขาด 1 แต้มต้องซื้อไม่ได้ ห้ามให้ยอดติดลบ. เพดานรับแต้มของห้องมีผลตอนรับแต้มจากงาน ไม่ได้ห้ามใช้แต้มที่มีอยู่
3. **อัปเกรด:** ต้องเป็นเจ้าของและมีระดับก่อนหน้าจริง เช่น Lv2 -> Lv3 จ่าย 3. ห้ามข้ามระดับ, จ่ายเกิน Lv5 หรือซื้อ Lv1 ซ้ำ. หลังสำเร็จแสดง `ก่อน -> หลัง`, ราคาที่จ่าย, ยอดคงเหลือ, ราคาอัปเกรดครั้งหน้า
4. **สลับตัว:** ไม่มีราคา แต่งตั้งตัวที่เป็นเจ้าของได้ทีละหนึ่ง; เปลี่ยนตัวแล้วคำนวณโบนัสใน tick ถัดไป ไม่ย้อนเวลาให้โบนัสหรือหักทรัพยากรย้อนหลัง
5. **จบอวกาศ:** การรีเซ็ตเมืองไม่คืนแต้มที่เคยจ่าย และไม่ลบ balance, ownership, level หรือประวัติ ledger. รางวัลถาวร 1 ชิ้นจาก Prestige แยกจากแต้มพิเศษเมืองโดยสิ้นเชิง

ตัวอย่าง: มี 0 แต้ม -> ทำงานที่มีสิทธิ์ 2 ชิ้น ได้ 6 -> ซื้อนักเก็บเกี่ยว Lv1 ราคา 4 เหลือ 2 -> อัปเกรด Lv2 ราคา 2 เหลือ 0 -> งานถัดไปได้ 3 -> อัปเกรด Lv3 ราคา 3 เหลือ 0. ตัวละครอื่นยังซื้อไม่ได้จนสะสมแต้มเพิ่ม

### กฎความเป็นธรรมและการแก้ไขย้อนหลัง (ต้องอนุมัติก่อนเขียนโค้ด)

- ครูตั้ง `เปิด/ปิดการรับแต้ม` และเพดานแต้มจากงานต่อช่วงเรียนได้ แต่ต้องแสดงกติกาก่อนนักเรียนทำงาน; ห้ามเปลี่ยนย้อนหลังแบบเงียบ ๆ
- หากงานถูกแก้ไขหรือส่งซ้ำ ไม่จ่ายเพิ่ม. หากครูเพิกถอนผลสำเร็จ ให้มีรายการ `reversal` อ้างรายการรับเดิมและแจ้งเหตุผล; ห้ามลบ ledger. ถ้าแต้มถูกใช้ไปแล้ว ไม่สร้างยอดติดลบหรือยึดตัวละครเงียบ ๆ; ตั้งสถานะให้ตรวจและกำหนดนโยบายร่วมกับครูก่อนเปิดจริง
- การย้ายห้องต้องไม่คูณแต้มงานเดิม; ใช้ `Student.id` และตัวระบุงานที่ถูกต้อง ไม่ใช้ชื่อ/รหัสนักเรียนเป็นคีย์. การรีเซ็ตคะแนนห้องเรียนเดิมไม่ควรล้างกระเป๋าเมืองโดยอัตโนมัติ
- เกมต้องเล่นจบได้โดยไม่มีตัวละคร. ห้องที่งานน้อยหรือไม่มีการเปิดรับแต้มยังเล่นเนื้อหาหลักได้เหมือนกัน; pilot ต้องตรวจความต่างระหว่างห้องก่อนยืนยันราคา
- คำสั่งรับ/ซื้อ/อัปเกรดต้องใช้ transaction และ idempotency key; ทดสอบกดซ้ำ, สองแท็บ, network retry, rollback และ audit โดยไม่แสดงข้อมูลส่วนตัวใน log

| --- | --- | --- | --- |
| **นักเก็บเกี่ยว** - อาหารเชิงรุก | ผลผลิตคนหาอาหาร `+8 / 12 / 16 / 20 / 24%` | เมื่ออาหารต่ำกว่า 25% ของคลัง เพิ่มโบนัสคนหาอาหารอีก `+8%` เฉพาะช่วงนั้น | เก็บผลไม้ด้วยมือได้อาหาร `+1` ต่อครั้ง (ยังต้องรอ cooldown) |
| **ผู้ดูแลชุมชน** - ประคองประชากร | อาหารที่ประชากรใช้ `-4 / 6 / 8 / 10 / 12%` | เมื่ออาหารเป็น 0 คนงานยังเหลือผลผลิต `30%` แทน `25%` | ประชากรเติบโต `+10%` เฉพาะช่วงที่อาหารสุทธิไม่ติดลบ |
| **นักสำรวจ** - วัตถุดิบ | ผลผลิตคนตัดไม้และขุดหิน `+6 / 9 / 12 / 15 / 18%` | กิจกรรมตัดไม้/กะเทาะหินให้ผลเพิ่ม `+1` ต่อครั้ง | ความจุไม้และหิน `+10%` ขณะประจำเมือง (เมื่อสลับออกต้องจัดการส่วนเกินโดยไม่ลบทรัพยากร) |
| **นักเล่าเรื่อง** - วิจัยเร็ว | ผลผลิตนักปราชญ์ `+8 / 12 / 16 / 20 / 24%` | วิจัยยุคหินลดต้นทุนความรู้ `5%` | ความจุความรู้ `+10%` ขณะประจำเมือง (ไม่ลบยอดส่วนเกินเมื่อสลับ) |

| **ผู้จัดการโรงงาน** - throughput | ผลผลิตโรงงานอุตสาหกรรม `+4 / 6 / 8 / 10 / 12%` | แสดงแผนผัง input bottleneck และเวลาที่สต็อกจะหมด | ตั้งลำดับความสำคัญการใช้ input ระหว่างโรงงานได้ 1 ชุด (ไม่สร้างทรัพยากรเพิ่ม) |
| **นักพลังงาน** - เชื้อเพลิง | พลังงานต่อหน่วยเชื้อเพลิง `+5 / 8 / 11 / 14 / 17%` | เชื้อเพลิงสำรองของเมืองใช้ได้นานขึ้น `+5%` | โรงงานพลังงานลด input เชื้อเพลิง `-5%` |
| **นักขนส่ง** - โซ่อุปทาน | ความจุวัตถุดิบอุตสาหกรรม `+5 / 8 / 11 / 14 / 17%` | เพิ่มช่องกำหนดคลังสำรอง 1 ช่อง (กัน input สำหรับโรงงานที่เลือก) | เพิ่มช่องคลังสำรองอีก 1 ช่อง; ย้ายของตามลำดับ ไม่เพิ่มทรัพยากรจากศูนย์ |

| ตัวละคร / แนว | ค่าหลักระดับ 1 / 2 / 3 / 4 / 5 | เอกลักษณ์ระดับ 3 | เอกลักษณ์ระดับ 5 |
| --- | --- | --- | --- |

| **โปรแกรมเมอร์** - automation | ความเร็วงานอัตโนมัติ `+4 / 6 / 8 / 10 / 12%` | ตั้งกฎเปิด/หยุดโรงงานตามสต็อกได้ 1 กฎ | ตั้งได้ 2 กฎ; ไม่ auto-buy/auto-research และต้องมี command receipt |
| **นักวิจัย** - วิทยาศาสตร์ | ผลผลิตความรู้ยุคข้อมูล `+6 / 9 / 12 / 15 / 18%` | ลดต้นทุนวิจัยยุคข้อมูล `5%` | ลดเวลาโครงการวิจัยปลายยุค `8%` |
| **ผู้ประสานงาน** - เมืองสมดุล | ผลผลิตคนงานทุกสาย `+3 / 5 / 7 / 9 / 11%` | เมื่ออาหารสุทธิติดลบ แสดงการย้ายคนที่แนะนำ (ผู้เล่นกดยืนยันเอง) | เพิ่มความจุประชากร `+8%` ขณะประจำเมือง |

## ยุคอวกาศ: วางแผนโครงการปลายเกม

| ตัวละคร / แนว | ค่าหลักระดับ 1 / 2 / 3 / 4 / 5 | เอกลักษณ์ระดับ 3 | เอกลักษณ์ระดับ 5 |
| --- | --- | --- | --- |
| **ผู้นำภารกิจ** - ประกอบยาน | ความเร็วประกอบชิ้นส่วนยาน `+5 / 8 / 11 / 14 / 17%` | แสดง critical path ของชิ้นส่วนที่ขาด | ลดเวลาขั้นประกอบสุดท้าย `8%` ไม่ข้ามวัสดุที่ต้องใช้ |
| **นักวัสดุ** - วัสดุขั้นสูง | ผลผลิตวัสดุอวกาศ `+5 / 8 / 11 / 14 / 17%` | input ของเครื่องแปรรูปวัสดุ `-5%` | คลังวัสดุอวกาศ `+10%` ขณะประจำเมือง |
| **นักขับยาน** - เตรียมการเดินทาง | ความเร็วทดสอบระบบยาน `+5 / 8 / 11 / 14 / 17%` | ลดเวลาทดสอบซ้ำหลังการปรับแต่ง `5%` | เพิ่มช่องทดสอบระบบพร้อมกัน 1 ช่อง โดยยังจ่าย input ทุกช่อง |
| **นักวางแผน** - เลือกลำดับ | ลดต้นทุนโครงการอวกาศ `2 / 3 / 4 / 5 / 6%` | แสดงต้นทุนรวมของสองลำดับประกอบที่ผู้เล่นเลือก | สลับลำดับโครงการที่ยังไม่เริ่มได้ฟรี; ไม่คืนวัสดุของขั้นที่ทำเสร็จแล้ว |

## จุดเสี่ยงที่ต้องแก้ก่อน implement

1. **โบนัสคลังเมื่อสลับตัว:** ห้าม clamp แล้วลบทรัพยากรส่วนเกินเงียบ ๆ; เสนอเก็บยอดไว้แต่หยุดผลิตเพิ่มจนต่ำกว่า cap ใหม่ และห้ามซื้อที่ทำให้ยอดเกิน cap ตามกติกาที่กำหนด
2. **โบนัส input/output โรงงาน:** การผลิตยังเป็น all-or-nothing ต่อ step. ตรวจ input, output cap และหัก/เพิ่มจากสูตรเดียวกัน ฝั่ง UI ใช้ helper เดียวกับ engine
3. **แต้มจากงาน:** ห้ามนำ `submission.score` ดิบมาแปลงตรง ๆ เพราะงานเช็กลิสต์เก็บเป็น bitmask; ต้องใช้ academic-score flow ตรวจสถานะงานที่ครูอนุมัติ แล้วออก ledger แยกพร้อม unique source key
4. **ธุรกรรมซื้อ/อัปเกรด:** แต้มและระดับตัวละครต้องเปลี่ยน atomically กับ command receipt/revision; replay, สองแท็บ, ครูแก้/ลบงาน, นักเรียนย้ายห้อง และ rollback ต้องมีนโยบายชัดเจน
5. **ความเป็นธรรม:** ไม่มีงานที่ให้แต้มพอในบางห้องต้องไม่ทำให้เล่นจบไม่ได้; ทดสอบ affordability ต่อชั้นเรียนและไม่ใช้ตัวละครเป็นประตูเนื้อหา
6. **สมดุล 500 ชั่วโมง:** จำลอง 4 สายหลักทั้งไม่มีตัวละคร/ระดับ 1/ระดับ 5, รอบแรกและหลัง Prestige; ค่า 500 ชั่วโมงเป็นเวลาเป้าหมาย ไม่ใช่ timer บังคับ

## แผนเริ่มงาน

1. อนุมัติชื่อ/บทบาทและราคา พร้อมเลือก 4 ตัวหิน + 4 ตัวสำริดสำหรับ pilot ก่อน
2. เขียนสเปก ledger แต้มพิเศษเมืองจากงานที่ครูเปิดสิทธิ์และกฎย้อนหลัง/แก้ไข/ย้ายห้อง
3. เพิ่ม engine modifiers แบบ deterministic, snapshot version และ test ทุกตัว/ทุกระดับ/สลับตัว/อดอาหาร/คลังเต็ม/รีเซ็ต
4. ทำหน้า roster เปรียบเทียบค่าก่อน-หลัง ซื้อ อัปเกรด และแต่งตั้ง รองรับมือถือและไทย/อังกฤษ
5. ทำ staging playtest ตรวจเวลาหาแต้ม, ความเข้าใจทางเลือก, ผลต่อ pacing และไม่มีตัวใดเป็นคำตอบที่ดีที่สุดทุกสถานการณ์ ก่อนขยายไปอีก 3 ยุค
