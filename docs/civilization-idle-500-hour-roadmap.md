# Civilization Idle: แผนห้ายุค รอบแรกเฉลี่ย 500 ชั่วโมง

สถานะ: Phase 0-6 เสร็จระดับโค้ดและ local QA; Phase 7 local balance gate ผ่านแล้ว และรอ remote staging pilot | 27 พฤศจิกายน 2026

## คำจำกัดความและเป้าหมาย

**500 ชั่วโมง = เวลาตามปฏิทินตั้งแต่เริ่มเมืองจนจบยุคอวกาศครั้งแรก** ไม่ใช่เวลาเปิดหน้าจอหรือเวลาคลิกสะสม (ประมาณ 21 วัน) เป้าหมายสำหรับผู้เล่นทั่วไปที่เข้าเกมเป็นช่วง ๆ คือค่ากลางราว 500 ชั่วโมง; ไม่ล็อกประตูด้วยตัวจับเวลา 500 ชั่วโมง ผู้เล่นวางแผนดีอาจจบใน 350-400 ชั่วโมง ผู้เล่นสบาย ๆ อาจใช้ 650-750 ชั่วโมง ตัวเลขทุกตัวเป็นสมมติฐานจนกว่าจะผ่าน simulation และ pilot

ตั้งเป้าเวลาเล่นแบบ active รวม 12-25 ชั่วโมง กระจายเป็นช่วงสั้น ๆ หลายสัปดาห์ ไม่มี daily streak หรือบทลงโทษเมื่อไม่เข้าเกม และไม่บังคับเล่นตอนกลางคืน ต้องเปิดเมืองแล้วมีการตัดสินใจที่มีความหมายภายใน 1-3 นาที

**สถานะจริง:** GameEdu มี engine/content/UI ครบ Stone, Bronze, Industrial, Information, Space และ Prestige ใน worktree แล้ว พร้อม schema/content v6 และ migration จากเซฟเดิม แต่ยังไม่ได้ deploy, push schema หรือเปิด feature flag. เมื่อยานอพยพเสร็จ ผู้เล่นเลือกรางวัลถาวรหนึ่งชิ้น ยืนยันสองขั้น และเริ่มรอบใหม่แบบ atomic พร้อมประวัติ audit.

## เส้นทาง 5 ยุค (baseline ผู้เล่นทั่วไป)

| ยุค | ช่วงเวลาสะสมเป้าหมาย | เวลาเฉพาะยุค | สิ่งใหม่ที่ต้องตัดสินใจ | เป้าหมายเปลี่ยนยุค |
| --- | ---: | ---: | --- | --- |
| หิน | 0-45 ชม. | 45 ชม. | อาหารสุทธิ, จัดคนงาน, พื้นที่คลัง, วิจัยหลายแขนง | เกษตรกรรม + เมืองเลี้ยงตัวเองได้ |
| สำริด | 45-120 ชม. | 75 ชม. | โซ่ทองแดง -> สำริด -> เหล็ก, เปิด/หยุด/อัปเกรดโรงงาน, สำรองวัตถุดิบ | พลังไอน้ำ + โซ่โลหะเสถียร |
| อุตสาหกรรม | 120-225 ชม. | 105 ชม. | พลังงาน/เชื้อเพลิง, เครื่องจักร, การจัดลำดับงานผลิต | ระบบไฟฟ้าและโรงงานอัตโนมัติพื้นฐาน |
| ข้อมูลข่าวสาร | 225-350 ชม. | 125 ชม. | งานวิจัย/ข้อมูล, ประสิทธิภาพเครือข่าย, automation ที่ต้องเลือกลำดับ | โครงสร้างการสื่อสารและวิทยาศาสตร์อวกาศ |
| อวกาศ | 350-500 ชม. | 150 ชม. | วัสดุขั้นสูง, พลังงาน, การประกอบยานเป็นหลายขั้น, เลือกการลงทุนสุดท้าย | โครงการอพยพสำเร็จ -> เลือกรางวัลถาวรหนึ่งชิ้น -> รีเซ็ต |

**ทุกยุคต้องมีอย่างน้อย 3 จังหวะ:** เริ่มด้วยระบบใหม่ที่เข้าใจได้ -> มีทางเลือกอัปเกรด/คอขวดที่แก้ได้หลายวิธี -> milestone ปลายยุคที่สรุปสิ่งที่เรียนรู้. ห้ามทำเวลา 500 ชั่วโมงด้วยราคาที่พุ่งขึ้นโดยไม่มีการตัดสินใจใหม่

## โครงสร้างอัปเกรดหลายระดับ

| ระบบ | ขอบเขตเสนอ | ความหมายของระดับ | หลัก balance |
| --- | --- | --- | --- |
| กิจกรรมกดเอง | 1-10 | ผลตอบแทนต่อครั้งดีขึ้นและ cooldown ลดลงจนถึงค่าต่ำสุด | ช่วยกู้คอขวด แต่ไม่ควรชนะ passive ระยะยาว |
| อาคารคลัง/ที่อยู่ | 1-20 ตามประเภท | ความจุ/ประชากรเพิ่มแบบค่อยเป็นค่อยไป | มี soft cap หรือ diminishing returns; ไม่ปล่อยราคาข้าม cap ที่ต้องใช้ซื้อ |
| งานคน/ทักษะอาชีพ | 1-10 mastery ต่อสาย | เพิ่มประสิทธิภาพเฉพาะอาชีพ ปลดล็อกวิธีจัดงาน | ความชำนาญไม่แทนจำนวนคนหรืออาหารฟรี |
| โรงงาน/พลังงาน | 1-15 ต่อชนิด | throughput เพิ่มตามระดับ โดย input เพิ่มตามจริง | แสดง gross, net และเหตุผลที่หยุด; upgrade ต้องจ่ายวัตถุดิบจริง |
| วิจัย | node ปลดล็อก + วิจัยซ้ำแบบจำกัดบางสาย | node เปิดกลไกใหม่; repeatable ให้โบนัสเล็กที่มีเพดาน | ไม่ทำต้นทุนไร้ขอบเขตหรือโบนัสคูณทับจนเลขล้น |
| โครงการปลายยุค | 3-5 ขั้น | สร้างชิ้นส่วน/ความพร้อมต่อเนื่อง | เปิดทางเลือกจัดสายผลิต ไม่ใช่กดรอ progress bar เดียว |

สูตรต้นทุนเริ่มทดลอง: `cost(next) = floor(base * growth^currentLevel)` โดย growth แยกชนิดประมาณ 1.12-1.30 และเพดานระดับชัดเจน; โบนัสต่อระดับควรลดผลตอบแทนส่วนเพิ่มเมื่อสูงขึ้น ค่าเหล่านี้ **ยังไม่ใช่กติกาจริง** ต้องจำลอง affordability, storage cap, อัตราผลิตสุทธิ และกรณี starvation ทุกระดับก่อนลง engine. ป้องกัน softlock ด้วย manual recovery, downgrade/พักสายผลิตที่ไม่เสียความคืบหน้า และเป้าหมายที่บอกทรัพยากรที่ขาด

## กลยุทธ์ที่ทำให้เวลาจบต่างกัน

- สาย **ประชากร/อาหาร** ลงทุนเสถียรภาพและแรงงานก่อน เร่ง passive ระยะยาวแต่เริ่มวิจัยช้ากว่า
- สาย **วิทยาศาสตร์** เปิดเทคโนโลยีเร็ว ใช้ต้นทุนโอกาสของคนงานและคลัง ต้องแก้ปัญหาอาหาร/วัสดุ
- สาย **โรงงาน/พลังงาน** เน้น throughput และโซ่วัตถุดิบ ต้องบริหารการขาด input และ output cap
- สาย **สมดุล** ไม่เร็วที่สุดในแต่ละด้าน แต่ความเสี่ยงคอขวดต่ำ

วางทางเลือกเป็น trade-off ที่ UI แสดงก่อนกด ไม่มีเส้นทางเดียวที่เก่งที่สุดทุกยุค; เวลาที่ต่างกันมาจากการตัดสินใจ ไม่ใช่โบนัสเติมเงิน, สุ่มโชคแรง หรือเงื่อนไขล็อกเวลาตายตัว

## Offline และประสิทธิภาพ: ต้องแก้ก่อนตั้งเป้า 500 ชั่วโมง

Baseline เดิมจำกัด offline **8 ชั่วโมงต่อการกลับมา**. Phase 1 เพิ่มเป็น 72 ชั่วโมงและใช้ adaptive step เฉพาะสถานะที่รักษาผลเดิมได้; เส้นทางที่มี converter ยังใช้ step ละไม่เกิน 1 วินาทีเพื่อความถูกต้อง

1. ออกแบบนโยบาย offline ใหม่ เช่น ให้ผลสูงสุด 24 ชั่วโมงต่อครั้งก่อน pilot แล้วทดสอบผู้เล่นที่ห่าง 48-72 ชั่วโมง; แจ้งเวลาที่ได้และเวลาที่ไม่ได้นับอย่างตรงไปตรงมา. ไม่ทำให้ต้องล็อกอินทุก 8 ชั่วโมง
2. ปรับ engine เป็น event/segment stepping หรือวิธีคำนวณที่พิสูจน์ว่าเทียบเท่ากับ 1-second reference ในกรณีอาหารหมด, cap, converters, population growth และ action completion; ห้ามคูณ rate ด้วยเวลาทั้งก้อนอย่างไร้เงื่อนไข
3. Benchmark การ sync 24/48/72 ชั่วโมงบนสภาพแวดล้อม Render และทดสอบ concurrent commands, retry, idempotency; ตั้ง budget latency/CPU จากผลจริงก่อนเปิดใช้
4. แสดงสรุปกลับมาเล่น: ผลผลิตสุทธิ, bottleneck, milestone ที่ผ่าน, สิ่งที่ควรทำต่อ; ไม่สัญญาว่า automation จะซื้ออาคาร/วิจัยแทนผู้เล่นขณะ offline เว้นแต่กำหนดกติกานั้นชัดเจน

## จบยุคอวกาศและรีเซ็ตหนึ่งรางวัล

- เงื่อนไข: วิจัย/สร้างชิ้นส่วนโครงการอวกาศครบ, ยานพร้อม, ผู้เล่นกดเปิดหน้าสรุป; **ไม่มีรีเซ็ตอัตโนมัติ**
- หน้า preview แสดงรางวัลถาวรที่เลือกได้ **หนึ่งอย่างต่อรอบ**, โบนัสและเพดาน, สิ่งที่รีเซ็ต/คงอยู่, เวลาเล่นรอบนั้น และคำยืนยันสองขั้น
- รางวัลตัวอย่าง: เพิ่มประสิทธิภาพอาหารขั้นต้น / เร่ง Science ช่วงต้น / เพิ่มคลังเริ่มต้น / ลด input โรงงานเล็กน้อย. เลือกได้ 1 จากหลายแบบ; ไม่ให้แต้มสะสมไปซื้อหลายชิ้นในรอบเดียว
- โบนัสถาวรต้องมีเพดานและเป็น sidegrade พอให้รอบใหม่รู้สึกต่าง แต่ไม่ทำให้ผ่าน 5 ยุคทันที. เป้ารอบถัดไปค่อยปรับหลังเห็นข้อมูล pilot; **500 ชั่วโมงนี้หมายถึงรอบแรกเท่านั้น**
- Server ทำการ award + increment run + snapshot รอบใหม่ใน transaction/revision เดียว มี command receipt กันกดซ้ำ/สองแท็บ, เก็บประวัติรอบก่อนสำหรับ audit และกู้คืน. ไม่กระทบ Student score, Gold หรือผลการเรียน

## การวัดว่า “สนุก” ไม่ใช่แค่ “นาน”

- ทดสอบ scripted agents อย่างน้อย 4 กลยุทธ์และสถานการณ์เล่นเป็นช่วง/หายไปหลายวัน ตรวจเวลาจบและจุดติดของแต่ละยุค
- Pilot แบบสมัครใจใน staging: วัดเวลาตามปฏิทิน, active minutes, จำนวนการตัดสินใจที่มีผล, milestone, session return และคำถามสัมภาษณ์ว่าทำไมเลือกอัปเกรดนั้น โดยไม่เก็บชื่อ/รหัสนักเรียนใน telemetry
- เกณฑ์ตั้งต้น: ไม่มี softlock, ไม่มีช่วงที่ผู้เล่นกลับมา 3 ครั้งแล้วยังไม่มีการตัดสินใจหรือปลดล็อกใหม่, ค่ากลางจบรอบแรก 400-600 ชั่วโมงหลังมีข้อมูลเพียงพอ; ผู้เล่นเร็ว/ช้าต้องไม่ถูกบังคับให้รอหรือถูกลงโทษ
- ถ้าเวลายาวแต่ผู้เล่นรู้สึกว่าได้แค่รอ ให้เพิ่มทางเลือก/feedback/automation ที่ควบคุมได้ก่อนเพิ่มต้นทุน. ถ้าจบไวเพราะ exploit ให้แก้สูตรและ cap ไม่เพิ่มตัวจับเวลาบังคับ

## ขอบเขตเทคนิคและ rollout

- ใช้ `src/lib/civilization-idle/` เป็น engine deterministic และ content catalog; UI ใน `src/components/civilization-idle/`; API/session/feature flag เดิมเป็นขอบเขตสิทธิ์
- เพิ่ม schema/content version และ migration ที่รักษาเมืองยุคหิน/สำริด; ทดสอบ serialization, invariant, command replay, stale revision, concurrent reset, offline, number overflow
- ถ้าขยายตัวเลขเกิน precision ของ JavaScript ต้องเลือกชนิดจำนวน/serialization ที่มั่นคงก่อนเขียนข้อมูล ไม่คัดลอก `break_infinity.js` จากต้นแบบโดยอัตโนมัติ
- Dark deploy -> staging pilot -> balance review -> เปิดรายห้อง; rollback โดยปิด flag และเก็บเซฟไว้. ห้ามเปลี่ยนโครงสร้างข้อมูล production ทั้งก้อนโดยไม่มี backup/restore rehearsal

## สิ่งที่ต้องตัดสินใจก่อนเริ่ม Phase 0

1. ยืนยันว่า **500 ชั่วโมงคือค่ากลางรอบแรกตามปฏิทิน** และ active time เป้า 12-25 ชั่วโมง
2. ยืนยันขอบเขต 5 ยุคและชื่อยุค: หิน, สำริด, อุตสาหกรรม, ข้อมูลข่าวสาร, อวกาศ
3. ยืนยันว่าจบอวกาศเลือก **รางวัลถาวร 1 ชิ้นต่อรอบ** โดยไม่ใช้ Legacy Points แบบซื้อหลายชิ้น
4. ตกลงนโยบาย offline ที่ไม่ลงโทษนักเรียนที่ไม่ได้เปิดเกมทุกวัน และแผนเก็บข้อมูล playtest อย่างเคารพความเป็นส่วนตัว
